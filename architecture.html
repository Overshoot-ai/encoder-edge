What happens after both embeddings are ready

The branches do not remain separate, and their vectors are not added together. vLLM constructs one ordered sequence and generates the answer from it.

1. Text vectorsT1, T2, T3…
Each row has 3,840 numbers.
2. Visual vectorsV1 through V264
Each row also has 3,840 numbers.
3. One sequenceT1 T2 BOI V1…V264 EOI T3
4. TransformerAttention processes text and visual rows together.
5. Next tokenThe LM head chooses the next answer token ID.
6. Readable textThe detokenizer converts the ID to text, streams it, and repeats.

First principles: what are these objects?

The model only operates on numbers. Words and pixels must both be translated into the kind of numerical rows that the Gemma transformer was trained to understand.

ScalarOne number
0.42
VectorOne row of numbers
[0.2, -1.1, ...]
MatrixMany equal-width rows
[264, 3840]
TensorThe general software name for an array of numbers. A vector and a matrix are both tensors.

Text becomes text vectors on H200

"Describe this" ↓ tokenizer [17291, 736] integer IDs ↓ embedding table [T1, T2] 2 vectors each T = 3,840 numbers

The token IDs are only dictionary indexes. Gemma's learned embedding table turns each ID into one width-3,840 vector.

+

Image becomes visual vectors on Mac

raw pixels ↓ patches + vision encoder [V1, V2, ... V264] 264 vectors each V = 3,840 numbers

The vision encoder does not output words. It outputs 264 learned numerical descriptions of the image.

What “same latent space” means

The text embedding layer and the trained vision encoder both output rows with 3,840 coordinates that Gemma has learned to interpret. Individual coordinates do not have simple labels such as “redness.” Meaning is distributed across patterns of many numbers.

Same width alone is not enough. Random 3,840-number rows would be meaningless. Gemma's vision encoder was specifically trained to translate visual information into a representation compatible with the language transformer.

“Combine” means place rows next to each other in sequence order
TEXT ROWS VISUAL ROWS FROM MAC MORE TEXT ROWS [T1] [T2] [BOI] [V1] [V2] [V3] ... [V264] [EOI] [T3] Every bracket above contains exactly 3,840 numbers.
✕ No text + image addition
✕ No averaging
✕ No image-to-text conversion

Why there are image placeholders

The prompt initially contains one <image> marker. vLLM expands it into 264 reserved positions because the Mac produced 264 visual vectors. Those reserved rows tell Gemma where the image belongs relative to the words.

What happens after the transformer: the LM head scores possible next-token IDs, vLLM chooses one, and the tokenizer decodes that ID into readable text. The new token is added to the sequence and this repeats until the answer is complete. The image vectors are never decoded back into pixels or separately converted into words.

The replacement step, literally

This is not a tensor-to-vector conversion. A vector is one row of numbers; a tensor is the container holding many rows. Both branches must produce rows of exactly 3,840 numbers.

1. Tokenizer reserves 264 positions The prompt contains one image marker. vLLM expands it into 264 repeated image token IDs between beginning/end image control tokens.
Describe this [BOI] [IMAGE_ID] × 264 [EOI] please
2. Both sides provide width-3,840 rows Text IDs go through the H200 embedding table. The Mac has already produced the visual rows. These are the same width, but encode different information.
text rows: [T1] [T2] ... image slots: [ _] [ _] × 264 Mac sends: [V1] [V2] ... [V264] Tn and Vn each = 3,840 numbers
3. Replace, do not combine The code selects every row whose token ID is image_token_id and overwrites those rows in order with V1 through V264.
BEFORE: [T1] [T2] [ _] [ _] ... RECEIVE: [V1] [V2] ... AFTER: [T1] [T2] [V1] [V2] ...
Result: one ordered sequence of text and visual vectors. That whole sequence is the input tensor passed into the Gemma language transformer.
